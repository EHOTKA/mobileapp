# app-platform Specification

## Purpose

Задаёт платформенный контур Android-приложения: конфигурацию сборки, манифест, ориентацию
экрана, полноэкранный режим и требования к разрешениям и иконке. Реализация —
`app/build.gradle.kts`, `app/src/main/AndroidManifest.xml`, `MainActivity.setFullScreen`.

## Requirements

### Requirement: Приложение собирается как единый Android-модуль

Проект MUST собираться одним application-модулем `com.example.game` на Kotlin с
`compileSdk` 34, `minSdk` 24, `targetSdk` 34 и байт-кодом JVM 1.8, без сторонних игровых
движков — только AndroidX и Material.

#### Scenario: Сборка debug-артефакта
- **WHEN** выполнен `sh gradlew assembleDebug`
- **THEN** сборка завершается успешно на Gradle 9.0.0 с AGP 8.3.0 и даёт один APK

#### Scenario: Минимальная поддерживаемая версия
- **WHEN** приложение устанавливают на устройство с Android 7.0 (API 24)
- **THEN** оно считается поддерживаемым и запускается

### Requirement: Игра идёт только в портретной ориентации

Активность MUST быть зафиксирована в портретной ориентации и MUST обрабатывать смену
конфигурации самостоятельно, без пересоздания.

#### Scenario: Поворот устройства во время забега
- **WHEN** игрок поворачивает устройство
- **THEN** ориентация остаётся портретной, `MainActivity` не пересоздаётся
  (`configChanges="orientation|screenSize|keyboardHidden"`) и забег продолжается

### Requirement: Игра занимает весь экран без системных панелей

Приложение MUST скрывать статус-бар и навигационный бар в иммерсивном режиме:
`WindowInsetsController` на API 30 и выше, устаревшие флаги `systemUiVisibility` ниже, с
повторным применением при каждом `onResume`.

#### Scenario: Возврат из фона
- **WHEN** активность возобновлена
- **THEN** системные панели снова скрыты

#### Scenario: Транзитный показ панелей
- **WHEN** пользователь свайпнул по краю экрана
- **THEN** панели показаны транзитно и автоматически скрываются
  (`BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`)

### Requirement: Манифест объявляет только используемые разрешения

Манифест MUST содержать только разрешения, реально используемые в коде: `VIBRATE` для
тактильного отклика. Разрешения без реализации в манифесте быть не должно, поскольку они
влияют на декларацию Data Safety в магазине.

#### Scenario: Вибрация при уроне
- **WHEN** персонаж получил урон
- **THEN** вибрация выполнена, и для этого достаточно `VIBRATE`

#### Scenario: Сетевого кода нет
- **WHEN** в приложении отсутствуют обращения к сети
- **THEN** разрешение `INTERNET` в манифесте отсутствует

### Requirement: Иконка запуска берётся из фирменных ресурсов проекта

Приложение MUST использовать иконку launcher из собственных `mipmap`-ресурсов проекта, а
не системную заглушку, и MUST показывать узнаваемое изображение на лаунчере.

#### Scenario: Иконка на устройстве
- **WHEN** приложение установлено и открыт лаунчер
- **THEN** `android:icon` указывает на `@mipmap/ic_launcher` и отличается от системной заглушки

#### Scenario: Разбор манифеста
- **WHEN** прочитан `AndroidManifest.xml`
- **THEN** ни `android:icon`, ни `android:roundIcon` не ссылаются на `@android:drawable`

### Requirement: Отрисовка аппаратно ускорена

Приложение MUST включать `hardwareAccelerated`, чтобы покадровая отрисовка Canvas на
высокой частоте не становилась узким местом.

#### Scenario: Отрисовка кадра
- **WHEN** `GameView` рисует кадр
- **THEN** используется аппаратно ускоренный конвейер (`android:hardwareAccelerated="true"`)
